# FinRisk知识库下一阶段改进建议

日期：2026年10月18日。范围：案例库、法规库、检索表示、证据阅读材料、版本与评测交接。Agent编排、工具注册、前端及在线决策由另一窗口负责。本文为建议，尚未执行数据改动或收费实验。

## 1. 总体判断

当前案例库无需重新全量生成。9639份有效候选、主体案件与行为记录已经形成，V2.1也已合并5份既有修正。主体、条件、例外、引文和不确定性字段已有实现，后续应检查其内容及实际导出范围，而非重复建立相同字段。

最值得解决的是：有用案例未进入初始候选；命中后展示的原文与主体、行为范围不完全一致；法规条件虽存在，语义及适用环节仍可能误用；版本与证据限制需要被下游准确读取。优先增量补丁、小样本对照和明确验收，不启动全库互审或重复抽取。

## 2. 优先级与具体交付

|优先级|建议|本窗口交付|理由与验收重点|
|---|---|---|---|
|P0：交接前|核对当前候选、索引与证据版本兼容性|一页交接说明、版本依赖表、少量读取样例|避免另一窗口读到旧稿，或将当前稿与不兼容索引混用；此风险尚未证明在另一窗口已实际发生|
|P0：质量|修正命中原句与实际展示范围|针对失败文书的范围补丁、同行为补充与扩展阅读标记|优先防止机构／个人、表格多行、行为／管理责任被混同|
|P1：召回|试验话术—机制—监管表达的检索辅助表|小规模通用表达表、来源支持和适用限制、独立评测名单|处理首轮漏召回；不把合成表达写成真实处罚事实|
|P1：边界|补核核心法规适用范围、效力及容易混淆的条件|现有12机制的边界修订、依据与待核记录；高价值专项材料|优先处理已暴露的事实误读、环节混用和来源状态问题|
|P1：证据|固化证据包与精确回源说明|统一字段说明、注册原文区间、来源限制、读取样例|已存在的条件与限制必须随证据交接；引文可回源和语义适用分开检查|
|P2：扩充|按实际业务补缺口与近邻边界|少量新规则卡／对比说明及新题，记录生成与审核来源|根据营销输入和错误频率选择，逐步补范围，不机械追求27标签各自一套规则|

## 3. P0：先把已有成果准确交给下游

### 3.1 固化版本和依赖

已有`version.json`、文件索引和SHA，不需要另造一套ID。新增交接表应明确：

1. 当前内容入口为V2.1 `effective_candidates.jsonl.gz`中的`draft`，原文与全量投影复用仓库V2。
2. 哪些索引输入没有变化、哪些解释字段已有修正；5份修正对应33单元的排名文本未变，是局部兼容证据，不能推导任意未来变更均无需重编码。
3. 案例内容、检索投影、法规条文及规则卡分别登记版本和指纹；解析、引用和向量缓存失配时明确报错或返回待核。
4. 用一份普通文书、一份多主体文书、一份修正文书、两份法规读取样例，核验ID、当前稿、证据位置及来源身份一致。

本窗口负责可验证的交接材料；运行时如何加载、注册与拒绝不兼容版本，由另一窗口实施。本次未读取另一窗口最新代码。

### 3.2 修展示范围，优先于全量加长文本

E02曾出现前缀对应某个主体，但下方返回整张多主体表的情况。E01后续小试中，固定排序仅修返回范围D1，有用片段134/210→137/210；这只是该轮模型银标小试，不代表已全量采用。

建议先从已知问题文书做10—20份定向核查，交付以下分层材料：

- 命中的连续原句及其原文位置。
- 有明确绑定的同主体、同行为补充。
- 可选的扩展原文，注明其可能包含其他主体或行为。
- 归属不明、重复原句、多位置匹配的显式歧义说明。

检索短文本、用于核查的详细原文、字段解释分别保存。未知归属保持未知，不能根据名单或相邻位置自动分配责任。已有稳定ID和引文绑定继续复用。验收同时看全文和实际展示片段，不能把全文相关直接当成片段充分。

## 4. P1：增强可检索性，先做小表和对照

### 4.1 依据与增量方案

最新全库实验99个已知直接支撑配对中，51个未进入任一路Top100，另6个被融合截断；重排前共损失57个。2026-10-16机制／片段联合实验也有两道新回访题未召回全库中已确认存在的直接案例。继续只调整精排难以解决这些遗漏。

建议先为8—12个现有机制建立通用检索辅助表达，每机制约5—8条，覆盖自然话术与监管表述的差异。例如围绕“指导本人作不实回访答复”，整理本人代答、冒名代接、透明预约等相关但不同的表达，明确区分适用条件。表达可以是合成辅助信息，但每条需记录来源类型；它不是监管原文或已发生事实。

先做BM25辅助字段或静态查询辅助表的小对照；保留原文路径，不把推测机制当硬过滤条件。若要加入BGE索引，则重新编码确有变化的文本并登记版本。Agent是否使用这些表达改写查询，由另一窗口决定。

### 4.2 不重复已经做过的实验

这项建议不同于已做的“4张机制卡第三候选路”：E03该次没有显示主指标增益，不建议直接扩量。此次先验证表达覆盖能否改善实际遗漏；不能把新增表达表称为已经提升召回。

验证时在全9639篇竞争范围内检索，使用事先冻结的新话术；开发失败题只作回归。保持用户确定的BM25:BGE=1:1，保留DeepSeek重排配置。比较初始候选的已知直接参考覆盖、Top1、MRR和实际片段帮助，并检查相邻机制误召回。没有完整分母时继续称“已知参考覆盖”，不称全库真实Recall。

辅助表达不得摘抄正式测试题、答案或qrels。涉及已看过的机制和来源时保留关联说明，不能仅凭文字不同宣称独立。

## 5. P1：法规库补边界、范围与核验状态

法规首版已有主体、产品、渠道、条件、例外、所需事实和禁止推断字段。修复版也有12机制操作条件，建议在这些材料上形成小范围修订：

1. **同义表达与不成立条件**：区分“按真实理解答复”和“要求把不理解回答成理解”；为解释歧义保留例子与不适用说明。合成边界例放在解释层，不能冒充真实正常案例。
2. **业务环节范围**：回访确认、订立合同、文书确认、客户记录分别描述；尤其处理已有M11误用于回访环节的问题。
3. **当前事实口径**：区分说话人陈述、独立背景与审查者未取得的材料；这是数据和规则说明的交接要求，不在本窗口修改Agent提示词。
4. **效力与来源**：优先补存核心官方原件、核对核心来源的版本及生效／失效信息，区分目录状态和个案适用性；L011／L012专项材料核实后再增补。
5. **覆盖说明**：现有27标签中16类有候选规则关联，11类没有独立边界设计。优先关注营销场景常见的绝对化、不当比较、弱化风险提示等；需要核对现有条文是否足够，只在真实缺口上补规则。标签关联不代表规则已充分覆盖。

条文原文、模型解释、检索辅助词与合成示例分别保存。与真实历史处罚案例关联法条时，应核对条款版本和行为时点；无法确认则保留候选关系，不把现行版本自动套给所有旧案。不得将本建议中的例子当作对具体业务的法律裁定。

## 6. P1：让下游能正确使用已有证据

知识库侧宜提供一份字段和读取样例，覆盖：

|信息组|交接内容|
|---|---|
|身份与版本|file_id、case／behavior／unit ID及对应版本／指纹|
|来源与引文|source_id、原文精确区间、原文指纹、原始文本；显示规范化时保留映射|
|适用范围|主体角色、业务环节、产品、行为、条件、例外与未知；已有字段按真实值导出|
|事实与解释|监管原话、模型概括、推断标签分别标记|
|质量与限制|候选／人工审核身份、归属歧义、版本效力待核、案例与规则的适用限制|

检索服务产生的分数、相关等级、query相关理由和限制属于运行时信息，应规定其随证据传递；不把它们伪装成静态案例事实。分数不代表当前输入的违规概率。

现有稳定ID、证据表和读取工具继续使用；重点是核对实际导出是否遗漏。精确引文优先由注册区间读取，避免让模型重新抄写。此前271条引用中41处差异仅为空白，仍有2处非空白差异；需要同时区分字面位置正确与语义支持正确。

## 7. 评测与资源安排

先使用离线读取、SHA、引用区间和既有错误记录核查P0事项，项目付费API调用为0，但会话及本机处理仍有成本。模型语义生成、新向量编码和新收费实验属于后续执行，应另列明确范围、时间与预算；本次仅完成文档建议。

知识库补丁应通过小规模新输入验证：例如先冻结24条业务文字，包含风险、正常边界及信息不足，正式测试只用于最终评价；开发题与来源关联单独登记。条件成对题不当作独立样本，合成模型银标不改称人工金标。完整Agent判断、预算与耗时测评归另一窗口，本窗口关注案例是否找到、实际证据能否回源、范围是否清楚、法规依据和关键条件是否齐全。

建议顺序：版本交接与已知范围补丁 → 检索辅助表达小试及核心法规边界核验 → 独立新输入确认 → 仅对有明确收益的部分扩量。两天内交付以这批小范围成果为目标，实际耗时应以首批处理和核验为准。

## 8. 当前不建议全量铺开的内容

- 再次抽取9639份或全量恢复模型互审：现有证据指向局部表示、范围与取证问题。
- 全库生成背景前缀：此前E02增益有限，且有范围问题；[Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)提供设计参照，仍须以本项目实测为采用依据。
- 全局GraphRAG、RAPTOR、事件强合并或扩建多Agent：现有研究尚未证明足够收益，且不属于当前知识库最小改进。
- 继续把已见36题调到满分，或修改参考以提高成绩。
- 改动已确认的1:1融合权重，或把任意候选标签直接当作确定违法判断。
