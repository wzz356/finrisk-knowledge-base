# FinRisk：BM25 + BGE → RRF → rerank离线测评方案

日期：2026-10-12。用户已确定BM25与BGE双路召回、RRF融合和模型重排。本文明确首轮参数与测评口径；尚未接入BGE、下载权重、生成向量或运行召回测评。

## 首轮链路与参数

查询 → 并行BM25 Top100 / BGE稠密向量Top100 → 按unit_id合并 → 等权RRF Top100 → BGE reranker重排100个片段 → 按case_id聚合 → Top5/10/20案例及支持片段、原文回链。

| 环节 | 首轮配置 |
| --- | --- |
| 检索单元 | 单一主体/行为片段为主，并保留补充原文结构片段；绑定来源、case/behavior/unit ID和版本 |
| 共享检索文本 | 原文片段 + 简短、有来源依据的身份/角色/时间/必要条件前缀；前缀与原文分存 |
| BM25 | 复用现有中文单字/双字分词，k1=1.5、b=0.75，Top100 |
| BGE embedding | 建议BAAI/bge-m3，首轮只使用稠密向量；文档与查询使用同一固定权重版本 |
| 向量比较 | L2归一化后余弦相似度；首轮精确搜索，避免把近似索引漏召回混入知识库质量诊断 |
| RRF | 两路等权，排名从1开始，常数60；候选并集至多200个唯一单元，取融合Top100 |
| rerank | 建议BAAI/bge-reranker-v2-m3；逐对输入查询与候选片段，按模型相关性分降序 |
| 案例聚合 | 同一case取最佳片段分作为案例分，保留其他支持片段；同文书的不同受罚主体保持不同case |
| 标签处理 | 自动风险标签、marketing未知等不作前置硬过滤；只执行明确权限/来源限制及用户明确指定的筛选 |

这些TopK、分词和候选预算是本项目首轮工程参数，效果与耗时以实际测评为准。模型选择是建议；实现前核查已有权重、运行环境及硬件，记录实际模型revision、设备、精度和批大小。

## 检索单元与文本

一个行为单元保留：主体、责任角色、动作、对象、机制、行为时间、产品及否定/例外/未知等必要限定。长材料按主体和行为切分，超出编码预算时沿完整语义边界继续分块，保留父级和相邻块；截断情况进入日志。

同一单元在BM25与BGE中使用同一个unit_id和同一版背景文本。查询仅作约定的规范化，不把答案标签、已知正例ID或原文标题注入查询。原文结构片段若无法确定所属主体或具体行为，保留未知映射和来源级结果，不强行挂到某个受罚人。

前缀只包含可回源的事实与限定；例如“个人责任未明确”要保留，不能因为召回标签为inferred而写成个人确定实施。原文、前缀、召回标签及审核状态分别保存。

## BM25与BGE分工

BM25处理词面匹配，重点观察专业术语、文号、金额、主体和具体机制词查询。BGE将查询和片段编码为向量，用于语义相似排序，重点观察同义改写及未使用原文措辞的业务描述。两路都返回完整的unit_id、原始得分、排名及来源映射。

BGE-M3官方列出1024维表示、最长8192 token输入，并同时支持dense、sparse和multi-vector；本方案只使用其dense功能，保持用户指定的两路结构。官方也建议混合检索后重排。[BGE-M3模型说明](https://huggingface.co/BAAI/bge-m3)

文档向量离线批量生成并缓存；查询向量在查询时生成，可按查询SHA缓存。缓存键绑定检索文本SHA、前缀版本、模型revision、分词器和编码配置。正文或前缀变化必须使对应向量失效。

## RRF融合

对单元u：

```text
RRF(u) = sum(1 / (60 + rank_channel(u)))
```

只对该单元实际进入的通道求和；未进入通道的贡献为0，排名从1开始。按unit_id合并两路记录，先计算RRF，再取Top100。相同分数按固定unit_id顺序处理，保证重放稳定。RRF阶段使用排名，不额外混合BM25原始分、向量分、标签奖励或现有人工权重。[RRF公式及参数说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

## 模型重排与案例输出

reranker输入是“查询 + 一个候选片段”的文本对，输出相关性排序分。对RRF选出的100个片段统一重排，以重排分为主、RRF为同分处理依据。分数即便经sigmoid映射至0–1，也不代表经过校准的正确性或合规概率。[BGE reranker官方用法](https://huggingface.co/BAAI/bge-reranker-v2-m3)

重排后按case_id聚合，案例分取其最佳片段分。展示命中的具体behavior/unit和支持证据，保留同案其他命中片段；不按文件ID把多个受罚主体合成一案。

rerank只能对已进入候选池的单元重新排序。每条失败查询必须区分：双路均未召回、RRF截取丢失、rerank降序，以及正确文书内找错主体或行为。BGE/rerank未成功执行的结果单列失败，不把TF-IDF或规则回退记作BGE成功结果。

## 50条开发查询与对照

查询从已审100份材料构建，覆盖风险机制、场景、同义表达和主体/日期/法条条件。预先冻结查询与有原文支持的已知正例，并记录来源、角色及适用限制。避免复制原文长句；100份已经读过，属于开发诊断材料。

检索候选范围计划为主队列8509份；其未完成语义验收部分继续标candidate/pending，质量信号与出处随结果导出。比较旧库与新候选库时固定相同来源范围、查询、检索器、模型版本与候选预算，明确旧库缺少来源或身份映射的情况。另保留100份修订前/后的局部诊断。

每套库分别执行四组：BM25；BGE；BM25+BGE+RRF；BM25+BGE+RRF+rerank。除待比较的环节外，其余输入一致。查询/文档向量和重排结果按精确绑定复用缓存，避免重复推理。

记录每路Top100、并集、RRF Top100及重排后的Top5/10/20；指标包括文书命中、正确主体/行为命中、Hit@K、已知正例Recall@K、MRR及分阶段耗时。未标注候选不直接认作不相关；没有完整相关集时不宣称完整Recall或完整nDCG。输出合并候选池供人工抽查，标注机制匹配、条件不符、标签相似但事实不同等情况。

360份预留盲验正文和比赛测试题/答案继续不读取。正式全量验收在修复、配置冻结及真实人工核定后执行。本轮不部署在线RAG，不更改真实审批状态或桌面项目默认配置。
