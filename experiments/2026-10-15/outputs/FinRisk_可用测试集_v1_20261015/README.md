# FinRisk可用测试集v1

这是一份已经实跑的小型案例检索诊断集：20条业务输入、100份现有V2源文书，全部2000个问题—文书配对均已阅读全文标注。闭集Recall的分母在这100份文书内完整；另在原9639份文书上进行补充检索，两种范围分开报告。

## 如何使用

1. 读取`queries.jsonl`中的`text`作为检索输入。不要把`query_specs.jsonl`的关注机制、参考标签、相关F编号放入检索或重排提示。
2. 只对`corpus.jsonl`中的100份文书建测试索引；可直接取`closed_index_units.jsonl`中818个现有V2单元，保持其来源及文书映射。`file_id`是计分单位。
3. 为每道题输出按名次排列、去重后的文书列表，每行形如：`{"query_id":"KBT001","file_ids":["F001265","F001827"]}`。实际列表应来自检索，例子仅演示格式。
4. 使用随包的标准库评分入口；不需模型、API或原工作区才能计算指标：

```powershell
python '.\evaluate.py' --dataset '.' --rankings '.\rankings\closed100_ND.jsonl' --output '.\my_metrics.json'
```

把排名路径改为自己的结果即可比较。输出文件必须尚不存在，以保留每次实测记录。排名应精确包含全部20题，不漏题、不重复文书、不混入闭集之外的文件；这些问题会被拒绝，不自动补0。

## 相关性与指标口径

目标是文书对判断输入风险或辨析合规边界是否有帮助。0无关；1仅主题相同；2存在部分具体相邻帮助；3原文明示同一关键机制，能够直接支撑或形成关键条件对照。主指标统一只把3分当相关。相同金融主题、通用法条或泛称欺骗不能自动当直接证据；文书违法事实也不表示当前边界输入违法。

对第q题，Pq为100文书中的全部3分文书，Lq为去重的文书排名：

- Recall@K = TopK与Pq的交集数 / |Pq|，最终对20题分别计算后等权平均。
- MRR@20 = 首个3分文书名次的倒数，前20没有3分则为0，再对20题平均。
- Top-1命中率 = 第一份文书为3分的题数 / 20。
- 主NDCG@K采用二值相关性，DCG为相关文书的`1/log2(rank+1)`之和；IDCG按该题全部3分数量构造理想前K，再计算比值及题均值。现有实现用等价的固定增益3，缩放在比值中抵消。

例如KBT007的闭集ND Top20找到6份直接支撑，全部参考有8份，Recall@20=6/8=75%。KBT011有22份直接参考，即使Top20全相关，其Recall@20上限也只有20/22。不能把不同题的相关文书合在一起作为宏平均分母。

所有20题均有直接参考，没有零正例题。附分级NDCG另外报告，用2分增益1、3分增益3；它不改变主Recall、MRR或Top1门槛。不同NDCG库的增益约定不一致，使用TREC文件时必须对应上表等级/增益，不能重复指数化。

## 构建和审核

题目根据已有案例机制合成，未逐字复制处罚事实或嵌入罚单号、机构名称、F编号。先固定抽样和题目，再检索；排除此前12题的9份参考文书。语料含16份机制种子，补入相关/相邻机制案例至75份，再加入25份固定随机干扰文书。非种子文书以100—4500字符的可读全文为范围，100份合计63554字符。

两轮独立上下文各阅读全文判断2000对，不看种子角色、排名、对方标签。1930对原始等级一致，一致率96.5%；25处影响主指标或分级NDCG的分歧由主会话根据原文逐项裁定。另45处仅0与1分歧保留初标，明确记录；二者在两种计分下均为0。主会话额外检查了6个容易混淆的负例。最终0/1/2/3分布为1550/232/78/140，所有>=2引用均可在原文连续定位。

参考集冻结后，主会话才读取具体排名。所有标注都是模型判断，`human_approved=false`；这是一份可复核的模型银标测试集，还未经过你的人工验收。全库补充池采用单轮盲读及抽查，审核强度低于闭集双轮；补充结果与主参考集分别保留。

## 实测配置

BM25使用项目原中文单字/双字分词，k1=1.5、b=0.75；BGE为`BAAI/bge-small-zh-v1.5`、512维CLS及L2归一化。两路各取100单元，1:1 RRF、k=60，合并后前100单元交给两种重排。文书以最高单元得分聚合，文件同分按F编号排序。模型快照和索引/代码哈希均有记录；查询向量、全库文档向量和闭集子集绑定已核验，embedding和交叉编码器重排截断均为0。

DeepSeek使用非思考模式、temperature=0、每对最大512输出token、8并发，3877个实际评分精确覆盖4000个查询—单元映射，跨两个范围的123个完全相同输入复用。没有默认评分补缺。已知usage估算费用约$0.3616，38个未知usage失败请求另按预留记账，含这些不确定请求的保守峰值价预算记账上界$0.7897，低于本次2美元保护上限；实际账单以服务商为准。价格依据[DeepSeek官方价格表](https://api-docs.deepseek.com/quick_start/pricing/)，详细用量在`api_cost_audit.json`。

## 使用边界

这是精选小库和源案例合成问题，不能把闭集高分直接当全库或官方200题成绩，也不代表覆盖全部27类。20题较少，一题就改变Top1五个百分点；部分问题成对共享机制，部分罚单涉及同事件/不同责任主体，逐题结果存在相关性。另附14机制等权宏平均，作为题目数量偏差的敏感性观察，不更改主口径。

本次原文标签以整份文件判断；返回片段若缺关键事实，即使文件相关仍需要阅读上下文。全库可能返回闭集之外的新直接证据，因此“没有命中已知参考”不能直接解释为“没有帮助”。全库ND Top20经补标可计算实际Top1、MRR@20、Precision@K；仍不具备全9639×20的完整相关分母，不报告其真实Recall或完整NDCG。

今后若用这20题调提示、权重或候选量，它们就应转为开发集。最终效果需再用新业务输入和独立核定参考验证，避免在同一小集上反复优化后宣称泛化提升。
